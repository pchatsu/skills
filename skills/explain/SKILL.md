# Explain

指定されたコード変更について、要点を把握できる説明を作成してください。

背景:
- 解決したい課題、変更する理由など具体的な背景を説明する。
- 変更差分の場合、必要に応じて今回の変更に関連する既存のシステムについて説明する。

内容：
- 本質を説明することに重点を置く。
- コンポーネント感のデータフロー、通信を示すシステム図を必要に応じて作成する。フローはアニメーションなどで流れをわかりやすく説明する。
- 図解ルール：
  - コンポーネントの種類ごとに色を統一する(セマンティックな配色。例: API=青系、DB=緑系、外部サービス=橙系)
  - ライト/ダークどちらのテーマでも見やすい配色にする
  - ワークフローはスイムレーン形式(担当・レイヤーごとにレーンで区切る)で表現する
  - 複雑な構成は概要→詳細の段階的な見せ方にする(まず主要コンポーネントのみ、クリックや折りたたみで詳細を展開)
  - 図はSVGで描画し、ホバーで補足情報を出すなどインタラクティブにする
  - 色分けした図には凡例(色の意味を示すレジェンド)を添える
- 具体的なサンプル、図やグラフは積極的に利用する。
- オライリー本やソフトウェアのドキュメントのように、シンプルでわかりやすい文章で。
- 理解度をテストする5つの質問を作成する。難易度は中程度で意地悪な質問は避ける。

出力形式：
- CSSとJavascriptを含む単一のHTML
- セクションヘッダと目次を含む
- ASCII図は使用しない
- コードブロックには、`<pre>` タグを使用する
- トップレベルの構造にタブを使用しない
- ファイルは `~/Documents/explain/` 配下に保存する
