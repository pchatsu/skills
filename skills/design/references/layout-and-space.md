# レイアウトと余白

「AI生成っぽさ」が最も見抜かれやすいのはレイアウトである。等幅のカラム、すべてが中央揃え、どのカードも同じ形——これらが典型的な兆候になる。

## 原則

- レイアウトには**主軸**がある。左寄り、右寄り、上部重視、下部重視のいずれか。中央揃えはデフォルトであって、選択ではない。
- **非対称は意図的に見える。対称はAI生成に見える。** 迷ったらずらす。
- **余白はスケールであって、単一の値ではない。** スケールを1つ決め、どこでも使う。生の px 値を打ち込まない。
- **余白にバリエーションを持たせる。** すべての隙間が24pxなら、それはテンプレートに見える。同じレイアウトの中で小・中・大の余白を混在させる。
- **意図してグリッドを崩す。** 1箇所だけグリッドをはみ出す要素があるページは、一度もはみ出さないページより強く印象に残る。

## 余白のスケール

4pt基準、9段階。サイズではなく役割で命名する。

```css
:root {
  --space-3xs: 0.125rem;  /*  2px */
  --space-2xs: 0.25rem;   /*  4px */
  --space-xs:  0.5rem;    /*  8px */
  --space-sm:  0.75rem;   /* 12px */
  --space-md:  1rem;      /* 16px */
  --space-lg:  1.5rem;    /* 24px */
  --space-xl:  2.5rem;    /* 40px */
  --space-2xl: 4rem;      /* 64px */
  --space-3xl: 6rem;      /* 96px */
  --space-4xl: 9rem;      /* 144px */
}
```

- 兄弟要素間の余白には `gap` を使う。積み重ねた`margin`より扱いがきれいで、flex/gridと自然に連動し、崩れ方も予測しやすい。
- `margin` は光学調整やフローからの意図的な逸脱にのみ使う。並んだリスト要素の間隔に`margin`を使わない。

## グリッド

- ページレイアウトには**CSS Grid**、コンポーネント内部の配置には**Flexbox**を基本とする。
- メディアクエリなしで流動的なレスポンシブグリッドを作るには `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))` を使う。
- **アイコン→見出し→本文の3カラム均等カードをデフォルトにしない。** これはAI生成のフィーチャーグリッドの典型パターンである。`grid-template-columns: 1.2fr 1fr 0.8fr` のようにカラム幅を変える、12カラムのグリッドを敷いて要素ごとに異なるspanを与える、あるいは2spanのヒーローを含む4アップ構成にする、といった方法で崩す。
- 複雑なレイアウトには**名前付きグリッドエリア**を使い、ブレークポイントごとに名前を変える。

## 非対称のテクニック

- **左に広いマージンを取る。** 左側を恒久的なネガティブスペースとして扱い、ラベル用の狭いカラムと本文用の広いカラムに分ける。ラベルは見出しに添えるセクション番号やアイキャッチ的なラベルにはしない。本文レベルの小さなラベル（キャプション、脚注、日付など）に限定して使う。
- **ハンギングヘッダー——見出しラベルを左余白に置く構成。** デフォルトは単一カラムに積み上げるセクション見出し。誌面的なレイアウトを明示的に求められたときだけ、ラベルを左マージン・本文を右に流す構成を選ぶ（ラベルと見出しを分けて2カラムに置くパターンがAI的に見える理由は[`anti-patterns.md`](anti-patterns.md)の「セクションごとのアイブロウラベル」を参照）。
- **オフセットグリッド。** 奇数カラムを偶数カラムより広くする、あるいはその逆。
- **グリッドブレイク。** 引用、写真、罫線、数値など、1つの要素だけが意図的にカラムの境界をはみ出す。
- **上を広く、下をタイトに**（あるいはその逆）。セクションの余白を均等にする必要はない。
- **整列の一貫性。** セクション見出しの水平方向の整列は、その下に続く本文と意図的に呼応させる（左揃えの見出しには左揃えの本文、中央揃えの見出しには対称的な本文）か、意図的に外す（非対称グリッドから逸脱する見出し）かのどちらかにする。AIらしいミスに見えるのは*偶発的な*不一致——`max-width`と`margin-inline: auto`で中央寄せされた狭い見出しブロックが、その下の全幅・左揃えの本文の上に浮いてしまっているようなケースである。中央揃え、ハンギング、下揃え、非対称——どの見出し配置も選択肢として有効。守るべきは画一性ではなく意図性である。

## 奥行き表現

- 奥行きは**シャドウではなくウェイトとスケール**で表現する。太いウェイト、大きいサイズ、暖色寄りの色相のほうが、ドロップシャドウよりよほど階層を作れる。
- シャドウを使うなら次の2種類のどちらかに限定する。
  - **Whisper** — `0 1px 2px oklch(20% 0.01 <色相> / 0.05)`。ホバー中のカードに使う。
  - **Hairline** — `0 0 0 1px oklch(30% 0.01 <色相> / 0.06)`。1pxボーダーの代わりに使う。
- 複数のシャドウを重ねない。明るい背景に色付きのグロー効果を使わない。
- z-indexは**6段階、名前付きで管理する。** 数値を自由に決めない。

```css
:root {
  --z-base:     1;
  --z-raised:   10;
  --z-dropdown: 100;
  --z-sticky:   200;
  --z-modal:    400;
  --z-toast:    500;
  --z-tooltip:  600;
}
```

## 禁則事項

- **すべてを中央揃えにする。** 見出し・本文をすべて中央に置くのは、どのLLMも吐き出す典型的なテンプレートである。
- **`min-height: 100vh`のフルスクリーンセクション（表紙スライドなど）に中央揃えの一文だけ。** 避ける。
- **カード・イン・カード。** 枠線付きコンテナの中に枠線付きコンテナを入れない。どちらか一方にする。
- **画一的なフィーチャーグリッド。** 3カラム、3つのアイコン、3つの2行見出し、3つの3行本文——何かを変える。
- **すべてに均等なパディング。** カードのパディングとセクションのパディングとページのパディングが同じだと、リズムが平坦になる。
- **`z-index: 9999`のような場当たり的な値。** スケールを使う。
- **暗い背景でのシャドウによる偶発的なグロー。** 暗いカードにドロップシャドウをかけると光って見えてしまい、これは避けたい状態。

## ページ端のクリッピング

意図的にビューポートをはみ出す装飾要素（フルブリードのマーキー、小さい画面で幅を超える大きな見出し、カラムを越えて傾いた図版など）は、overflowを*視覚的には*見せつつ、ドキュメント全体を横スクロールさせない親要素で囲む必要がある。

デフォルトの実装は危険である。`width: calc(100% + 12vw)` の図版を `overflow: visible` のセクションに入れると、あらゆるビューポートでドキュメントが横スクロールしてしまう。タッチデバイスではページが壊れて見える。

**はみ出し要素には必ずグローバルなクリップを併用する。** スタイルシートの先頭に置く。

```css
html { overflow-x: clip; }
body { overflow-x: clip; }   /* 古いSafari向けのフォールバック */
```

`overflow-x: hidden` ではなく `overflow-x: clip` を使う理由:

- `clip` は子孫の `position: sticky` や `position: fixed` を保持する。
- `hidden` は新しいスクロールコンテナを作ってしまい、stickyを壊したり、はみ出す入力欄でフォーカスを閉じ込めたりする。

はみ出し要素は視覚的な広がりを保ったまま、ページは横スクロールしなくなる。同じパターンはフルブリードのマーキーや大きめの見出し、意図的な装飾のはみ出し全般に使える。

はみ出す要素を*含む*ヒーローやセクション自体は `overflow: visible` のままにする（そうしないと図版が親要素の端で切れてしまう）。`html` と `body` へのグローバルなクリップだけで安全策としては十分。

## 迷ったとき

レイアウトが破綻していないのに単調に見えるなら、出荷前に次のいずれかを試す。

1. はみ出し要素を1つ足す。
2. カラム幅のバランスを崩す。
3. 見出しやキーとなる要素を中央から外す。
4. カードを1つ減らし、余白に置き換える。
5. どこか1つのセクションのパディングを変えてリズムを崩す。
