# タイポグラフィ

タイポグラフィがデザインを運ぶ。書体選びを誤れば、他の何を工夫しても意味がない。

## 原則

- ページは単一フォントではなくペアリングで組む。ディスプレイ用書体＋本文用書体が最低構成。*単一フォントを使ってよいのは、それが意図的な選択である場合だけ*——たとえば全面モノスペースで組む端末的な世界観や、1書体だけで押し切るポスター的な見せ方などである。デフォルトは常にペアリング。
- 極端に振り切る。ウェイト200と800の組み合わせは意図的に見えるが、ウェイト400と600の組み合わせはただの初期設定に見える。
- サイズの段階は増分ではなく比率で作る。Major third（1.25）、Perfect fourth（1.333）、Perfect fifth（1.5）、Golden ratio（1.618）のいずれかを選び、それを一貫して使う。
- 行間はサイズに応じて変える。ディスプレイは詰め気味（1.05〜1.2）、本文はゆったり（1.5〜1.65）。
- 一行の文字数（measure）は45〜75文字の範囲に収める。デフォルトは `max-width: 65ch`。

## 「2＋1」ルール — 書体は最大3種まで

**1ページで使える書体ファミリーは最大3種。** ディスプレイ用1つ、本文用1つ、そして任意でアウトライヤー1つ——ワードマーク、ヒーローの数値、引用、マストヘッドなど、ページの中で1箇所だけ違う音を鳴らしたい場面に使う。4種類はやり過ぎ。2種類が基本形。3種類は上限であり、控えめに使う。

パターン:

```css
:root {
  --font-display:  "Fraunces", ui-serif, Georgia, serif;       /* 見出し、ヒーロー */
  --font-body:     "Geist", ui-sans-serif, system-ui, sans;    /* 本文、UI */
  --font-outlier:  "Geist Mono", ui-monospace, monospace;      /* ワードマーク＋ヒーロー数値専用 */
}
```

アウトライヤーは第三の書体ではなく、ページの中で一箇所だけ違う声を出すための「レジスター」である。ルール:

- **アウトライヤーの登場箇所はページ全体で2箇所以内。** ワードマーク＋ヒーロー数値、あるいは引用文＋マストヘッド、といった具合に2枠まで。5箇所ではない。3箇所目に手を伸ばしたくなったら、それはもうアウトライヤーではなく「3つ目の本文フォント」であり、過剰である。
- **アウトライヤーは1つの役割だけを担う。** ブランド名、見出しの数値、宣言的な一文など、特定の種類のコンテンツに紐づける。役割が決まったら、その役割に出てくるものはすべて同じアウトライヤーで統一する。あるボタンラベルには使い、別のボタンラベルには使わない、というのは避ける。
- **モノスペースも1つの書体として数える。** ディスプレイにFraunces、本文にGeist、コードブロックにGeist Monoを使うページは3書体を使っていることになる。それ自体は問題ないが（コードがアウトライヤーの役割を担っている）、そこに4つ目を紛れ込ませない。
- **同一ファミリーのウェイト違いは1書体として数える。** Geist 400とGeist 700は1書体。そこにFraunces を組み合わせれば2書体。さらにGeist Monoを足せば3書体になる。

ほとんどのページでは2書体が正解である。3書体はブランド訴求が強く、ワードマークに本文とは異なるレジスターが必要なページのために取っておく。

## 避けるべき定番フォント

以下はどのLLMも既定で選びがちなフォントである。明確な理由なしに選ばない。

- **サンセリフ:** Inter, Roboto, Open Sans, Lato, Poppins, Source Sans, Nunito, Montserrat, Raleway, Work Sans, DM Sans, system-ui, Arial, Helvetica。
- **セリフ:** Merriweather、Playfair Display（本文用としては使いすぎで禁止。ディスプレイ用に控えめに使うのは可）、Lora、Source Serif、既定値としてのGeorgia。
- **モノスペース:** Courier New、既定値としてのConsolas、system mono。

ユーザーが明示的に指定した場合はそれに従う。それ以外は下記のカタログから選ぶ。

## フォントペアリングの考え方

固定の対応表を丸暗記するより、ブリーフから逆算して以下を判断する。

1. **声色を1語で言語化する。** クラシカル／技術的／無骨／柔らかい／上質／遊び心がある／抑制的、など。その声色に合うディスプレイ書体を上のカタログから選ぶ。
2. **本文はコントラストを作る相手として選ぶ。** ディスプレイがセリフなら本文はニュートラルなサンセリフに、ディスプレイが幾何学的なサンセリフなら本文はやや温かみのあるセリフに、というように「似すぎない」組み合わせを探す。
3. **ウェイトの対比を確認する。** ディスプレイと本文のウェイト差が小さいと、意図のないペアリングに見える。
4. **アウトライヤーは役割から逆算する。** コード、統計値、ブランド名など、そのページで際立たせたい1種類のコンテンツのために選ぶ。
5. **無料枠がデフォルト。** Fraunces、Geist、Bricolage Grotesque、Cabinet Grotesk、Sentient、JetBrains Monoなどは第一級の書体であり、妥協案ではない。有償ファウンドリーへの切り替えは、(a) ユーザーがライセンス済みであることを明言した場合、または (b) ユーザーが特定のファウンドリーの声色を名指しで要求した場合に限る。コード中でライセンス未確認の有償フォントを名指しすることは避ける——確認なしに実装すると、実機ではシステムフォールバックに落ちて壊れて見える。

## ワードマークのタイポグラフィ

ナビゲーションやフッターのワードマークは、本文とは異なるディスプレイ書体を使ってもよい。ページ全体の声色が濃い（誌面性が強い、ブランド性が強いなど）場合は**むしろ使うべき**——ワードマークを本文フォントに畳み込むと視覚的な階層が失われ、ページが「ブランドのない」印象になる。

```css
:root {
  --display:       "Geist", system-ui, sans-serif;     /* 本文＋見出し */
  --font-wordmark: "Fraunces", Georgia, serif;         /* ロゴ専用 */
}
.wordmark {
  font-family: var(--font-wordmark);
  font-weight: 600;
  letter-spacing: -0.015em;
}
```

推奨の組み合わせ（無料枠を基本とする）:

- **Geist本文 → Frauncesのワードマーク、IBM Plex Monoのワードマーク、あるいはBricolage Grotesque（太字）のワードマーク**
- **Frauncesの本文 → Geist Monoのワードマーク、Inter Tightのワードマーク**
- **system-uiの本文 → JetBrains Monoのワードマーク、Newsreaderのワードマーク**
- **Inter Tightの本文 → Frauncesのワードマーク、EB Garamondのワードマーク**

同一ファミリーに統一してよい場面: 本文の声色そのものがブランドを体現している、長文中心・単一カラムのページ。ワードマークが小さく、装飾ではなく組版として成立している場合。

対比のある書体を選ぶべき場面: グリッドや大きな数値など、視覚的に単調になりがちなレイアウトで、本文だけでは出せない違いをワードマークに持たせたい場合。

**SaaS的なページで同一ファミリーに畳み込むのは避ける。** サンセリフ本文＋同じサンセリフのウェイト違いだけのワードマークは「設計されていない」印象になる。本文にサンセリフ、ワードマークにセリフのSemiBoldを使うだけで、「これはブランドである」というレジスターが1つ加わる。コストはほぼゼロである。

## スケール

比率を1つ選ぶ。基本のデフォルトは**1.25（major third）**。本文16pxを起点にスケールを組み、ディスプレイサイズはレスポンシブ用にclampする。

```css
:root {
  --text-xs:   0.64rem;   /* 10.24px */
  --text-sm:   0.8rem;    /* 12.8px  */
  --text-base: 1rem;      /* 16px    */
  --text-md:   1.25rem;   /* 20px    */
  --text-lg:   1.5625rem; /* 25px    */
  --text-xl:   1.9531rem; /* 31.25px */
  --text-2xl:  2.4414rem;
  --text-3xl:  3.0518rem;
  --text-4xl:  3.8147rem;
  --text-display: clamp(2.75rem, 5vw + 1rem, 5.25rem);
}
```

**ディスプレイサイズの上限は5.5rem（88px）程度に抑える。** これを超えると、1280〜1440pxのビューポートで見出しどうしが窮屈になり、複数行の折り返しが必要になって「重厚」ではなく「大げさ」に見えやすい。ディスプレイ重視のテーマであっても上限は6rem（96px）とする。例外は12文字以内に収まる単語・数値1つだけのディスプレイ（統計値など）で、その場合は7remまで許容する。**デフォルトの出力形式は `clamp(2.75rem, 5vw + 1rem, 5.25rem)`。**

### 文書の見出しスケール

長文ドキュメント（自分用の理解ノート、共有用のレポートなど、スクロールする1ページのHTML）は、一発芸の大見出しを必要としない。必要なのは、H1〜H4が本文との対比で迷わず読み取れる、なだらかで一貫したスケールである。

- **比率は本文寄りの穏やかなものを選ぶ。** Major third（1.25）が基本。1.333（Perfect fourth）や1.618（Golden ratio）のような急な比率は、ディスプレイページ向けであり、長文では見出しの飛躍が大きすぎて章と章の連続感を壊す。
- 本文サイズ（16〜18px）を起点に、上の「スケール」で定義した`--text-*`トークンをそのまま流用してよい。

| レベル | 目安サイズ | ウェイト | 余白（前/後） | 備考 |
| --- | --- | --- | --- | --- |
| H1（文書タイトル） | 36〜48px（`--text-3xl`前後） | 700〜800 | 0 / 0.4em | 文書につき1つ。ページ最上部のみに置く |
| H2（章） | 26〜32px（`--text-2xl`前後） | 700 | 2.5〜3em / 0.6em | 前の余白を広く取り、新しい章の開始を視覚的に告げる |
| H3（節） | 20〜24px（`--text-lg`〜`--text-xl`） | 600 | 1.75〜2em / 0.5em | |
| H4（小見出し） | 17〜19px（`--text-base`よりわずかに大きい程度） | 600 | 1.25〜1.5em / 0.4em | 本文と紛れないよう、太さか色でのみ差をつけてもよい |

- **見出し前の余白は見出し後の余白より2〜3倍広く取る。** 詰まった見出しは「連続する本文の一部」に見え、適切に間を空けた見出しは「独立した区切り」に見える。
- **見出しレベルを飛ばさない。** H1 → H2 → H3の順を守る。飛ばすと文書構造（およびアクセシビリティツリー）が壊れる。
- **見出しには`id`属性を振り、目次（TOC）のアンカーにする。** 目次の項目文言と本文の見出し文言は完全一致させる——目次で「概要」、本文で「はじめに」のような表記ゆれを作らない。

### スライドタイトルのサイズ

プレゼンテーション（1画面=1トピック、16:9固定ビューポート）は文書と逆の制約を持つ。読者は手元の画面ではなく、部屋の奥や画面共有越しに見る。文字は「読める」ではなく「遠くからでも一瞬で読める」サイズにする。具体的なサイズ基準（表紙スライドのタイトル・セクション見出し・本文・キャプションなど）は[`responsive.md`](responsive.md)の「可読性の最低基準」表を正とする。

- **1スライドに収まる文字量はサイズと反比例する。** 目安として、本文28〜32pxなら箇条書きは5〜6項目・各1行以内に収める。文字量を削れない場合はフォントサイズを下げて詰め込むのではなく、スライドを分割する。
- 文書と違い、スライドは見出しの深い階層を必要としない。タイトルと本文の2段階でほぼ足りる。サブタイトルを足す場合も、本文とのサイズ差を大きく取る（+8px以上）。

## ウェイト

- 本文: 1ウェイトのみ（通常400または350）。強調のみ太字を使う。
- 見出し: 本文とのウェイト差を300単位以上つける。本文が400なら見出しは700か200——500や600は中途半端。
- 合成フォントを使わない。必要なウェイトのファイルを読み込む。単一ウェイトのファイルに`font-weight: bold`をかけて済ませない。

## 必須の実装

- すべてのWebフォントに `font-display: swap` を設定する。
- `size-adjust`、`ascent-override`、`descent-override`、`line-gap-override` でフォールバックのメトリクスを合わせ、CLSを防ぐ。
- データを表示する箇所には `font-variant-numeric: tabular-nums;` で等幅数字を使う。
- 書体が対応していれば本文にオールドスタイル数字を使う: `font-variant-numeric: oldstyle-nums;`。
- 正しいタイポグラフィ的な約物を使う: `" " — … ' '`。直引用符や `--`、`...` は使わない。

## 本文のルール

- 最小16px。14px未満はアクセシビリティを損なうので避ける。
- 行間は本文1.5〜1.65、ディスプレイはタイトに1.1〜1.3。**全角大文字（`text-transform: uppercase`）のディスプレイ見出しの行間の下限は1.0、推奨は1.02〜1.08。** 1.0を下回ると、ディセンダーのない大文字だけの行では次行の上端が前行のベースラインに衝突し、折り返した箇所のカンマと大文字が視覚的に融合してしまう。コンデンス系のディスプレイ書体ではこの問題がさらに悪化する。
- 一行の文字数は45〜75文字（`max-width: 65ch`）。
- 本文を全部大文字にしない。ハイフネーションなしの両端揃えを使わない。本文のletter-spacingは0.05em以上にしない。

## 見出しのルール

- ディスプレイサイズではトラッキングをタイトにする（書体に応じて`letter-spacing: -0.02em`〜`-0.04em`）。
- スモールキャップスやラベルではトラッキングをゆったりさせる（`letter-spacing: 0.08em`〜`0.14em`、`text-transform: uppercase`、書体が対応していればスモールキャップスを使う: `font-variant-caps: all-small-caps;`）。
- 見出しレベルを飛ばさない。`h1` → `h2` → `h3`。見た目は自由にスタイリングしてよいが、セマンティックな順序は守る。

## 禁則事項

- Inter、Roboto、Open Sansは使わない。system stackだけを唯一の書体にしない。
- 見出しにグラデーションテキストを使わない（`background-clip: text` にグラデーション塗り）。
- 単一フォントのページにしない。
- 本文を全部大文字にしない。
- 本文のフォントサイズを14px未満にしない。どの箇所でも10px未満にしない。
- 強制的な合成太字・合成イタリックを使わない。
- **1ページで使う書体ファミリーは3種類まで。** ディスプレイ＋本文＋アウトライヤー1つが上限。4種類は過剰。
- アウトライヤー書体を3箇所以上で使わない。ワードマーク＋ヒーロー数値が基本の組み合わせであり、3箇所目に手を伸ばしたくなったら本文書体に戻す。
